# Python SDK

Package `mqcache` (`sdk/python`), Python 3.9+, Windows (it drives MSMQ through its COM automation objects with `pywin32`).

```powershell
pip install mqcache
```

```python
from mqcache import CacheClient, Priority

with CacheClient("tcp:10.0.0.5", password="secret", decode_responses=True) as c:
    c.set("user:1", "alice", ex=300)
    c.incr("hits")
    c.hset("session:9", mapping={"ip": "10.0.0.1"})
    c.execute_command("PING", priority=Priority.HIGHEST)
    results = c.pipeline([("SET", "a", 1), ("INCR", "a"), ("GET", "a")])     # one message, atomic

    with c.subscriber("news", patterns=["alerts.*"]) as sub:
        c.publish("news", "hello")
        for msg in sub.listen():          # or sub.get_message(timeout=5)
            print(msg.channel, msg.text)
```

## API summary

| Area | Methods |
|---|---|
| Core | `execute_command(*args)`, `pipeline(cmds, atomic=True, raise_on_error=False)`, `send_no_reply(*args)` |
| Strings/keys | `get set(ex, px, nx, xx, keepttl) delete exists incr decr append expire pexpire ttl pttl persist type keys mget mset rename dbsize flushall save` |
| Hashes | `hset(key, field, value, mapping) hget hdel hlen hexists hincrby hgetall` |
| Lists/sets | `lpush rpush lpop rpop llen lrange lindex`, `sadd srem smembers sismember scard` |
| Server | `ping info config_get publish` |
| Pub/Sub | `subscriber(*channels, patterns=...)` with `subscribe psubscribe unsubscribe get_message listen close` |
| Options | `endpoint queue password timeout retries priority recoverable transactional use_journal use_dead_letter reply_host reply_scheme decode_responses subscription_renew transport` |

Errors: `ServerError` (`.code` is `ERR`, `WRONGTYPE`, `OOM`, `NOAUTH`, ...), `CacheTimeoutError`, `TransportError`, `MsmqUnavailableError`, `WireFormatError`; all derive from `MQCacheError`.

## How it differs from the .NET client

* No selective receive in the COM API, so replies for all threads are read by one waiter at a time and handed to their owners (`_ReplyDemux`).
* Queue names use `mqcache.pyreply.` / `mqcache.pysub.` so the .NET orphan sweeper (which owns `mqcache.reply.` / `mqcache.sub.`) never deletes a live Python queue. Orphans from crashed Python processes are not swept automatically.
* Not in 0.1: waiting for MSMQ acknowledgments, multicast subscribers.

## Testing

```powershell
cd sdk\python
pip install -e .[test]
pytest                                   # codec golden vectors + client logic, any OS
# against a running server (verifies the COM transport):
$env:MQCACHE_TEST_ENDPOINT = "."; $env:MQCACHE_TEST_QUEUE = "mqcache"
pytest tests/test_integration_windows.py -v
```

`sdk/testdata/golden.json` is generated by the reference .NET codec (`dotnet run --project sdk/tools/GoldenVectors`). CI regenerates it and fails when it differs from the committed file, so the .NET codec and every SDK stay byte-compatible.

## Writing another SDK

1. Implement chapter 8 (codec) and make it reproduce `sdk/testdata/golden.json`.
2. Implement the transport: send a message with `Label=mqcache.req`, `AppSpecific=1`, `BodyType=VT_ARRAY|VT_UI1 (0x2011)`, `ResponseQueue=<your private reply queue, DIRECT format name>`, then read the reply whose `CorrelationId` equals your message id.
3. Reuse the same request id on retries. Use your own queue-name prefix (not `mqcache.reply.`/`mqcache.sub.`).
